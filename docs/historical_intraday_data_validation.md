# QuantaAlpha 历史盘中数据准入与验证记录

- 版本：`1.2`
- 验证日期：`2026-08-13`
- 状态：`NO_SOURCE_PASSED`
- 适用范围：V4 盘中策略的隔离历史研究，不属于正式前向证据

## 1. 目标与运行边界

目标不是做一个依赖 Codex 每天触发的演示，而是让 QuantaAlpha 自己完成定时采集、信号冻结、模拟成交、记账、健康检查和告警。Codex 只参与开发、验证和故障处理，不在每日运行链路中。

当前正式权威仍是冻结的 `intraday_shadow_20260814_t1_reversal_v4`。本次只读探针没有修改 V1-V4 实现、声明、账本、盘中快照、Qlib Provider 或收益协议。历史数据只有通过本文件的准入合同后，才允许在独立目录实现研究适配器；不得回填或污染 V4 前向证据。

## 2. 为什么不能直接拿到数据就回测

V4 的 C1 排序公式为：

```text
max(-(14:50 price / previousClose - 1), 0) * turnoverPercent
```

模拟成交使用独立的 14:55 快照。因此，只有 OHLCV 不足以精确重放 C1；还必须有 14:50 时点可用的昨收与累计换手率。用收盘后的整日字段反推 14:50 数据会引入未来信息，用当前 CSI300 成分股回填历史则会引入幸存者偏差。

## 3. 历史数据准入合同

### 3.1 最低数据门

1. 至少覆盖 `252` 个有效交易日。该门只允许实现适配器，不等于盈利证据；正式收益判断仍服从 [收益有效性验证协议](profit_validation_protocol.md) 的多年度、成本和前向门槛。
2. 每日使用点时 CSI300 成分区间，不能用当前 300 只股票回填历史。
3. 每只个股必须有明确的 14:50 决策价、14:55 执行价、昨收和截至 14:50 的累计换手率。
4. 14:50 与 14:55 的目标股票字段覆盖必须为 `100%`；全体成分股核心字段覆盖不得低于 V4 的 `95%` 门。
5. 时间戳必须明确表示区间结束时点，交易日、午休、停牌、上市退市和涨跌停状态必须可判定。
6. 原始价、复权价和昨收的口径必须一致；跨除权日不得把原始分钟价与前复权日线价直接相除。
7. 原始响应、请求参数、抓取时间、来源、行数、缺失项和 SHA256 必须进入不可覆盖的 manifest。

### 3.2 无未来数据门

- 14:50 信号只能使用当时已经发布的字段。
- 禁止用当日收盘量、收盘换手率或收盘后修订值补齐 14:50。
- 如通过自由流通股本重建换手率，股本必须在该时点已知且有点时生效日期；不能使用当前股本回填历史。
- 14:55 之后的数据只能用于成交、结算和评估，不能返回信号计算。

### 3.3 经济有效性门

- 交易费用、印花税、滑点、T+1、最小手数和涨跌停不可成交规则必须与冻结模拟盘合同一致。
- C1 必须与同条件 B0 配对比较，不能只报告 C1 自身收益。
- 数据源切换、缺失填补和异常剔除规则必须在查看收益前冻结。
- 历史结果只能作为诊断；真正的晋级仍需要冻结后的前向模拟盘复现。

## 6. 通达信 `.htc` 技术结论

进一步只读探针确认：

- 通达信官方 `datatool.rar` 为 `645,267` 字节，SHA256 为 `4c36787b977b1de5eb1e3d9d6b69734aad42341369fe1440921cdd1010a582d6`。其中 V3/V4 Linux 工具均为静态链接的 32 位 Intel 80386 ELF，同时带有 32 位 Windows PE 程序，没有 macOS ARM 可执行文件。
- `go_tdx2db` 没有开源第四代 TIC 解码实现；Linux 路径仍调用上述外部 `datatool tick create` / `min create`，源码在 macOS/Windows 明确跳过 `tick` 和 `min`。
- 从未完成的 2026-08-13 G4 ZIP 临时样本中，可以按外层目录结构连续验证 `95` 个完整证券块：证券代码、日期、压缩/解压长度均自洽，每块 zlib 解压成功；这只证明容器层可读。
- 解压后的内部负载不是旧 `2ktic` 的直接兼容格式。2018 年 `ParseTicFile`/`pytdx` 逆向代码不能在未校验的情况下套用到 G4 数据，因此目前不能可信地产生逐笔或 1/5 分钟 K 线。
- 本机没有 Wine 或 QEMU；Docker Desktop 已安装但守护进程未运行。本次没有启动 Docker，也没有安装模拟器或下载全年数据，因为解析正确性和数据使用授权仍未通过前置门。

因此，`.htc` 的剩余问题不是普通 ZIP 解压，而是第四代内部格式验证和数据授权。启动容器只能运行现有黑盒转换器，不能自动解决许可证、跨日口径和结果校验。

## 7. Tushare 252 日样本可验收方案

Tushare 是目前唯一从官方字段合同上可以覆盖最低 `252` 日适配器技术门、并能无未来信息重建换手率的候选：

```text
turnoverPercent@14:50
  = sum(stk_mins.vol through 14:50)
    / (stk_premarket.float_share * 10,000)
    * 100
```

同一日的 `stk_premarket.pre_close` 用于原始收益分母，`stk_mins` 的 14:50/14:55 收盘价分别用于决策和模拟成交。历史 CSI300 点时成分仍使用已经验证的 Qlib 区间文件，不由 Tushare 当前成分回填。

准入前必须完成：

1. 用户自行获得 `stk_mins` 和 `stk_premarket` 权限，并把 token 只配置在本地 `TUSHARE_TOKEN`；不得写入仓库、日志或报告。
2. 先测 `600519.SH`、`000001.SZ`、`300750.SZ`，覆盖不少于 252 个共同交易日，确认 14:50/14:55 边界、停牌零量、单位和复权口径。
3. 用 2026-08-13 不可变腾讯快照交叉校验重建换手率；差异门槛必须在查看收益前冻结。
4. 验证分钟权限的速率、分页、重试和商业/研究使用条款，再估算 CSI300 全量下载量。
5. 不得把 252 日样本通过解释为盈利历史通过。当前盘前股本合同只有近约 2 年，而 [收益有效性验证协议](profit_validation_protocol.md) 要求至少四个完整年度中的三个年度为正；缺少的历史点时股本仍需另找来源。

官方当前权限表列出的个人价格为历史分钟 `2,000 元/年`、盘前股本 `500 元/年`，且分别开通；价格和覆盖可能变化，购买前必须在官网再次确认。其[数据服务协议](https://tushare.pro/document/1?doc_id=405)只授予个人、不可转让、非商业、可撤销且有期限的许可，并要求仅作个人使用；商业化、共享原始数据或向第三方提供服务前必须另行取得明确授权。本记录只说明技术与合同边界，不代替用户的法律判断。

当前 `.env` 没有配置 Tushare token，所以这里只是“可执行探针已经准备、真实权限仍阻断”，不是已通过的数据源。新增的 `scripts/qualify_tushare_intraday.py` 只在内存中取三个样本并打印脱敏报告，不写市场数据、不切换 Provider、不接触 V4 台账。无 token 时实测结果为 `BLOCKED`；即使 252 日、8,000 行截断门和 2026-08-13 腾讯交叉校验全部通过，也只返回 `SAMPLE_PASS`，并固定保持 `sourceQualified=false`、`adapterEligible=false`、`profitEvidenceEligible=false`。

本地配置好两项权限后可运行：

```bash
source scripts/qa_env.sh
python scripts/qualify_tushare_intraday.py
```

Token 只能放在本机未共享的 `.env` 或进程环境中，不得粘贴到聊天、命令行参数、日志或报告。

## 8. 当前实时更新状态

实时更新已经由仓库自己的 V4 链路完成，不需要等待历史适配器：

- `CoreFieldRealtimeClient` 按 `Tencent -> Eastmoney -> Sina` 顺序逐只补齐；个股必须有价格、昨收、换手率和合格时间戳，CSI300 基准只豁免无关的换手率字段。
- FastAPI 盘中采集器在交易窗口每 `60` 秒执行，原始帧按不可覆盖 JSON/GZIP、SHA256 和连续时槽链落盘；同一时槽幂等复用。
- 2026-08-13 最后一帧实测 `301/301`、当前交易日覆盖 `100%`、可用覆盖 `100%`，来源为 `a-stock-data/tencent-public`；下一窗口为 `2026-08-14 09:15 +08:00`。
- V4 自动协调器同样每 `60` 秒运行；生产 readiness 为 `READY 12/12`。若关键字段、时间或目标覆盖不满足合同，会在账本写入前失败关闭。

这证明自动采集和降级机制当前可运行，不证明未来上游永远可用，也不证明策略盈利。

## 9. Manager 决定

当前没有任何候选同时通过“至少 252 日、点时成分、14:50 累计换手率、14:55 价格、可控超时和批量稳定性”合同，因此不实现历史适配器，也不生成容易被误读的收益结果。

后续按以下顺序推进：

1. 正式 V4 继续每日自动积累完整前向数据，不需要 Codex 或浏览器保持打开。
2. 不为“实时更新”再新建重复适配器；生产继续使用已经通过真实 301 只验活的 V4 逐源降级链。
3. Tushare `stk_mins + stk_premarket` 只优先执行 252 日技术验收；在 token 与两项权限可用前不运行网络探针，在样本、许可、全量容量和四年度缺口关闭前不写生产适配器。
4. 新浪只保留为 OHLCV 候选组件。除非另一个点时来源能无未来信息地补齐累计换手率，否则不把两者拼成 C1 回测。
5. 数据合同通过后，才新增只读下载器、独立 manifest、缓存和配对回放测试；不得改写冻结 V4。
