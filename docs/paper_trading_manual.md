# QuantaAlpha A 股模拟盘使用手册

更新日期：2026-08-11

开始模拟盘收益验证前，先执行并满足 [QuantaAlpha 收益有效性验证协议](profit_validation_protocol.md)。本手册只说明模拟成交链路，不把链路跑通视为策略有效。

当前隔离运行的 C1/B0 前向观察盘请使用 [研究影子盘与实时数据使用手册](research_shadow_manual.md)。它保留历史 `REJECTED` 结论，不具备正式模拟盘资格。

## 1. 功能边界

这是 QuantaAlpha 自建的日频研究模拟盘。它读取本地 A 股日线数据；模型模式生成冻结换仓计划，手工模式接收完整目标持仓，并在下一可用交易日按规则模拟成交。

- 不连接同花顺、券商或真实证券账户。
- 不会提交真实委托，也不会产生真实资金损益。
- 模拟盘用于验证信号、撮合、费用和净值链路，不等于证明策略未来有效。
- 账户、信号、委托、成交和净值均持久化，重启前后端不会清空。

### 4.2 下一交易日执行

同步到晚于信号日的新行情后，再点击“执行下一交易日”。系统使用下一可用交易日开盘价模拟成交，并以当日收盘价更新净值。

没有更晚行情时，信号保持等待状态，不能使用信号日收盘价提前成交。这用于避免未来数据和同日成交偏差。

### 4.3 查看结果

页面会显示：

- 现金、市值、总资产和累计收益。
- “前向验证监控”中的观察阶段、沪深 300 累计收益、税费后超额收益和最大回撤。
- 20 日工程门、60 日早期数值门和 120 日较强数值门的状态。
- 当前持仓及可卖数量。
- 待执行信号和策略来源。
- 委托、成交、拒单原因和费用。
- 净值曲线。

A 股买入数量按 100 股整数手向下取整。Qlib Provider 中的价格是复权价格，系统使用同日 `$factor` 按 Qlib 的 `100 / factor` 规则换算复权数量，使成交金额、最低佣金和实际整手等价值与原始价格一致；页面显示因子折算后的股数和原始价等价值。模型行情缺少 `$factor` 时会在创建运行和成交前失败关闭。目标金额不足一手时会生成拒单记录，而不是静默忽略。

账本内部保留复权数量与复权价格以维持跨除权日的收益连续性。这与研究回测口径一致，但不等同于券商的逐笔分红、送转和红利税流水；进入真实资金评估前仍须单独对账公司行动和税务处理。

前向统计只接受同一个冻结模型快照、连续 Provider 交易日和完整沪深 300 基准。系统按每日净值几何复合计算策略与基准累计收益，再计算税费后超额；不是把每日收益简单相加。以下情况会把观察期标为无效或停止，而不会继续累计为盈利证据：

- 混入手工目标，或在同一账户中切换模型快照。
- 模型执行日缺少同一 Provider 的 `000300.SH` 基准行情。
- 净值日期在 Provider 交易日历中不连续。
- 最大回撤达到 `15%` 停止线；达到 `10%` 时显示预警。

研究影子盘已把这两条治理线落实为后端规则：10% 只告警；任一 C1/B0 达到 15% 后，配对状态变为 `RISK_STOPPED`，待撮合信号和新收盘信号都会被拒绝，且不会自动恢复。正式模拟盘仍需在获得合格 `PAPER_CANDIDATE` 后按同一原则单独验收。

页面通过 60 日或 120 日数值门不会自动把策略改成 `PAPER_VALIDATED`。还必须人工核查成交偏差、成本、集中度和收益来源，并按验证协议审批。

## 5. 手工目标模式

切换到“手工目标”后，可以输入证券代码和完整目标权重组合。手工组合与模型信号使用同一撮合和账本，适合验证单个场景。

- 证券代码格式示例：`600000.SH`、`000001.SZ`。
- 每次提交表示完整目标组合，不在新组合中的原持仓会进入卖出调整。
- 目标总权重不能超过 100%。
- 手工目标同样只能在后续交易日执行。

## 6. 每日运行流程

建议在交易日收盘且公开日线数据可用后执行。

### 6.1 安装新的完整行情快照

优先安装官方 `investment_data` 完整发布。命令会下载发布清单和归档，校验大小与 SHA256，并只安装到新的版本化目录；不会修改已有 Provider。只有 `--switch` 会更新运行配置：

```bash
cd /absolute/path/to/user/Documents/QuantaAlpha-main
source scripts/qa_env.sh
python scripts/install_investment_data_release.py --switch
```

指定发布可增加 `--release-tag YYYY-MM-DD`；已有离线归档可增加 `--source-dir <发布目录>`。安装和切换后重启前后端，再核对设置页的数据源、最新交易日和模拟盘账户。

官方发布暂时不可用时，可以按 [零 Token 日线扩展使用说明](zero_token_daily_market_data.md) 构建范围受限的腾讯 CSI300 扩展。该流程必须使用目标日保存的不可变双快照，并逐批审计；不得在现有完整 Provider 上原地合并，也不得把 2026-08-04 至 2026-08-06 的授权泛化到以后日期。

### 6.2 执行待处理信号并生成最新信号

```bash
python scripts/paper_trading_daily.py
```

该命令只应在活动快照已达到 `PAPER_CANDIDATE` 后加入每日任务。当前活动快照未达到该门槛，尝试生成模型信号会被门禁拒绝；不要通过修改状态文件或直接写数据库绕过。

脚本按以下顺序运行：

1. 若存在待处理信号且已有后续交易日，先执行撮合。
2. 若执行后没有待处理信号，再用最新行情日生成下一批模型信号。
3. 若没有后续行情，输出 `waiting` 并保持账本不变。

不要为同一天反复执行不同脚本来强制成交。所有输出中的 `signalId`、`runId` 应保留用于核对。

## 7. 撮合假设

当前默认规则：

- 信号日之后的第一个本地可用交易日成交。
- 使用次日开盘价，并计入 10 个基点滑点。
- 买入费率 0.05%，卖出费率 0.15%，受最低佣金约束。
- 买入按 100 股整数手取整。
- 执行卖出后再分配买入资金。
- 执行 T+1 可卖约束。
- 停牌、无有效开盘价和一字涨跌停场景会拒单。
- 当日收盘价用于持仓市值和净值更新。

模型快照模式还必须遵守冻结的 Qlib `TopkDropoutStrategy` 执行契约：

- `TopK`、`n_drop`、`risk_degree`、买入排序和卖出排序均随快照冻结，页面和 API 不允许临时改参。
- `hold_thresh` 必须是正整数并随快照冻结。旧版 `hold_thresh=1` 契约继续兼容；多日持有使用版本 2 契约。
- 首次建仓买入不超过 `TopK` 只；之后只卖出计划中的底部持仓，每日最多替换 `n_drop` 只，保留持仓不做权重再平衡。
- 买入成交日结束时持有交易日记为 1，此后每完成一个模拟交易日加 1，停牌持仓也计数。候选卖出股票未达到 `hold_thresh` 时显示为“持有期锁定”并继续持有。
- 与 Qlib 一致，持有期锁定不会取消同日已经选出的计划买入，因此持仓可能暂时达到 `TopK+n_drop`；后续换仓会在候选满足持有期时卖出并恢复到 `TopK`。
- 计划卖出完整可卖数量；卖出处理后，使用当时现金的 `risk_degree` 按计划买入数量等额分配。
- `forbid_all_trade_at_limit=true` 时，达到冻结涨跌停阈值的股票禁止任何方向交易，与 Qlib 策略生成规则一致。
- 信号保存生成时的当前持仓、持有交易日及双重哈希。执行前若持仓或持有交易日发生变化，系统拒绝整个执行并要求重新生成信号，不会部分成交。

手工目标模式仍按完整目标权重再平衡，不使用上述 `n_drop` 规则。两种模式共用费用、滑点、整手、T+1、持仓和净值账本。

由于当前日线数据缺少完整的逐时点 ST、除权和证券状态字段，一字板及 5% 涨跌停判断无法覆盖所有真实市场细节。

### 9.1 达到模拟盘盈利准入前还需要什么

1. 提出新的、可解释的经济机制，只冻结少量候选；候选、方向、标签、持有期、费用、门槛和试验总数必须在查看目标期收益前写入新协议。
2. 优先补齐更严格的点时数据，包括历史修订版本、公告盘中时间和更接近论文口径的宽基准；继续使用 BaoStock 代理时必须保留证据上限，不能直接晋级实盘。
3. 用确定性执行合同完成历史准入、完整收益矩阵和季度走步。近期收益、最新完整年度、IR、回撤、2 倍成本、相对 B0、bootstrap、DSR 和 PBO 必须同时过门。
4. 只为通过的 `PAPER_CANDIDATE` 冻结 Provider 指纹、模型、特征、股票池、并列排序、`TopK/n_drop/hold_thresh`、T+1、涨跌停/停牌和费用合同；训练、回测与每日推理必须使用同一合同。
5. 从空账本开始原样运行：20 个交易日验证数据与撮合一致性，60 日观察早期收益/风险，至少 120 日形成较强前向证据。期间不得根据表现改参数；改动即建立新候选并重新计时。
6. 每日核对数据新鲜度、信号日期、订单/成交、持仓、费用和基准净值；设置预警和停机规则。当前治理线为回撤 `10%` 预警、`15%` 停止新信号并复核，不代表保证盈利。

## 11. 常见问题

### 点击执行后提示没有后续交易日

这是正常保护。先完成新交易日数据同步，再执行模拟盘。

### 策略快照不可用

检查 `data/trading/paper/strategy_snapshot.pkl` 是否存在，再查看后端日志。不要从不可信来源复制 pickle 快照。

### 策略快照存在，但生成按钮不可点击

这是收益资格门正常工作。查看页面中的验证状态和原因；只有新的 `PAPER_CANDIDATE` 或 `PAPER_VALIDATED` 快照才能生成模型信号。不要手工篡改快照状态。

### 已存在待执行信号

先等待并执行当前信号。不要通过删除数据库来绕过队列。

### 目标数量与实际持仓数量不同

模型模式中的指示权重不表示每日全量再平衡；保留持仓数量本来就不会变化。除此以外，目标金额不足一手、停牌、价格无效、涨跌停限制或可用现金不足也会造成计划与实际持仓不同。以冻结换仓计划、委托拒单原因和成交记录为准。

### 执行时提示持仓已变化

模型信号生成后，账户被手工信号、重置或其他操作改变，冻结计划已经失效。系统会在创建执行记录前停止；核对账户后重新生成策略信号，不要修改数据库绕过持仓指纹。

### 数据同步部分股票没有新行情

停牌或上游暂缺数据时，同步器会保留该股票的已有历史。查看对应批次的 report 和 manifest，确认整体批次是否成功提升。
