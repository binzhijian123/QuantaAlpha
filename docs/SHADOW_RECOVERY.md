# 自动影子盘恢复与验收

本轮将中断的历史 V9 保留为审计记录，使用独立采集目录、声明与未来运行建立新证据。历史缺失交易不可补造，也不能把单次采集、网页健康或校准通过当作自动影子盘验收。

## 来源与数据版本

- V4 在行情响应收到后检查报价时点，限制为最多落后120秒、最多提前5秒，并绑定实际实现文件、依赖和来源契约。
- 新的采集入口为 `market_data.intraday_capture_v4`，不修改历史采集核心及 V9 冻结文件。默认生产客户端的输出才可以用于来源资格，测试注入客户端不可冒充生产证据。
- 中证指数[官方沪深300成分表](https://oss-ch.csindex.com.cn/static/html/csindex/public/uploads/file/autofile/cons/000300cons.xls)在本次取得的版本中，日期为2026-10-22，包含信立泰；原日线数据包仍包含信达证券。[上交所终止上市公告](https://www.sse.com.cn/disclosure/announcement/listing/stock/c/c_20261012_10834561.shtml)说明信达证券于2026-10-19终止上市。
- `scripts/build_current_membership_provider.py` 从完整官方表生成独立 Provider，只修正表中可验证的当日成分，不推断此前区间的实际调整日期，不修改原数据包或价格特征。清单记录原始表、解析记录和原 Provider 哈希；派生版本不能声称与原压缩包逐文件相同。
- 本次10月22日日线包的沪深300基准特征有效日期仍为10月21日。成分修正不会补写价格；正式日结前须独立取得并核验所需基准日线，不能用实时行情替代。
- 此缺口现已通过独立修复版本补齐：`benchmark_daily_repair.py` 重新采集两个TCP服务器的原始/复权闭市数据，并与腾讯完整40日窗口交叉核验，保留原审计阈值及指数day门，禁止SDK自动补算。只填补缺失的10个基准字段单元，不改原数据目录。运行时按实际特征文件树校验新版本；它不是旧缺失版本的追加后继，也不证明未来日结已通过。此前r2/r3声明与原件保留；新校准使用独立r4调度入口，生产V4行情字段不变。

可只读检查某个数据版本最后交易日的字段完整性：

```bash
python scripts/verify_shadow_provider_session.py --provider /absolute/provider/path --session YYYY-MM-DD
```

该检查包括300只成分股和基准的OHLC、成交量及因子。PASS仅代表结构与当日字段完整，来源资格、历史谱系、自动运行仍须分别验收。

## 来源资格

10月26日完整242槽校准通过，但同日收盘原件缺失，不能补做。27、28日各自唯一一次收盘对照均因换手率差超0.02而失败；28日校准虽通过原覆盖率门，实际只有241/242，缺10:13，不满足V10完整242槽要求。上述结果分别保留，不能拼接为通过。

已新增独立的分钟网格调度，修复相对轮询累计漂移造成的跨分钟漏槽；只采真实当前时槽，不传入人工时钟、不补历史。已预声明10月30日独立r4校准，等待实际整日证据。29、30日来源守候各有固定独立输出，已经尝试的日期不得重试或另换目录。中金公司[官方新增股份公告](https://static.cninfo.com.cn/finalpage/2026-10-27/1225627350.PDF)说明29日新增流通股上市；两源股本分母生效差可解释部分差异，但供应商实际分母尚未确证，不能据此换算原件强造PASS。
独立来源守候工具为 `scripts/watch_intraday_v4_qualification.py`。它从指定日期正式时段的真实生产快照中固定首个合格301样本，当天15:10后只调用一次原收盘对照；未完成尝试遇到跨日或不确定中断会保持MISSED/UNKNOWN，不用新请求替换失败结果。它需要独立存活的进程；进程健康不能证明收盘对照已完成，当前登录内运行也不等于注销或重启后的恢复。

2026年10月23日收盘实际对照结果为FAIL：两源均301条、其余8项门通过，1只股票换手率绝对差0.0235337067超过既定0.02。两TCP主机诊断一致；具体股本口径原因未知。保留失败证据、不降低阈值；未来日期重新取当天盘中与同日收盘证据，不能复用跨日样本。未通过来源资格及完整新校准时禁止启用V10。

在已安装项目依赖的环境下，使用项目的环境入口执行：

```bash
bash scripts/qualify_intraday_v4.sh realtime --provider /absolute/path/to/derived-provider
```

该命令保存隔离实时快照，要求300只成分股加基准共301条有效报价。返回成功只代表实时证据已取得，`qualificationPassed` 仍为 false。保留输出的 `snapshotFile`，同日15:00后执行：

```bash
bash scripts/qualify_intraday_v4.sh close \
  --provider /absolute/path/to/derived-provider \
  --realtime-snapshot /absolute/path/to/snapshot.json.gz
```

腾讯和独立 TCP 来源必须均有完整301条同日收盘数据，价格与昨收绝对差各不超过0.01，换手率差不超过0.02。保留原始 stale 标记与时间，禁止改写字段以通过资格。完整 PASS 才能冻结资格报告；收盘数值对照本身不证明实时新鲜度。

退出码：0为该命令阶段成功，1为失败，2为等待。休市返回的旧快照不算新采集。默认证据目录为 `data/market/a_share/intraday/v4_qualification`，不会写入历史生产目录。

## 完整校准与未来运行

1. 在未来交易日开始前冻结独立校准声明，固定 Provider、股票池、采集实现、60秒间隔、交易日和质量门槛。
2. 完整校准覆盖09:30–11:30、13:00–15:00共242个预期时槽；15:05后核验报告。不能把已有半日数据补成完整校准，也不能因缺失而降低门槛。
3. 校准通过后，另行冻结后续交易日的新协议和账本，验证 V4 来源资格及新协调器绑定。校准阶段禁止生成策略收益或自动决策。
4. 实际验证14:50决策、14:55执行价格绑定、正式日线日结、证据链、数据自动维护及进程恢复。需要连续交易日的验收必须等待真实时间。
5. 所有门通过后才允许覆盖已备份的篮球战术板仓库并改名 `QuantaAlpha`。远端发布前重新扫描源目录，根 `HANDOFF.md` 使用公开脱敏版，禁止上传 `.env`、行情、账本、日志、缓存和内部交接记录。

新入口中的 `shadow_recovery.py` 只负责经声明绑定的采集校准，不能替代新交易协调器。`QA_SHADOW_RECOVERY_DECLARATION` 是维护者的本地恢复入口；普通使用者仍在设置页配置自己的 API、模型和环境，不需要手动编辑冻结声明。

## 独立r4校准入口

维护者先使用 `scripts/freeze_shadow_recovery_r4.py` 冻结一个新的未来交易日；它仅生成声明，不改 `.env` 或启动服务。运行时显式选择该声明：

```bash
QA_SHADOW_RECOVERY_R4_DECLARATION=/absolute/path/to/frozen-r4.json \
  bash scripts/run_recovery_r4_backend_supervised.sh
```

默认使用独立的127.0.0.1:8012及独立守护进程、睡眠保护和日志。未来日期前只等待，不创建行情目录或取报价；声明当日按实际分钟的第5秒规划采集，慢请求返回后重新判断当前分钟。长时间阻塞仍可能缺槽，必须检查真实242/242。源码绑定、声明或永久时钟故障失败时readiness返回503。r4保持交易关闭、accepted=false；不能把该入口的健康或重启检查当作V10真实交易运行验收。旧入口不接受r4声明。

## 自动继续与运行边界

当前聊天自动化每日继续核验；盘中与收盘采集由独立持续进程负责，不依赖聊天恰好唤醒。自动化唤醒不等于后台服务或操作系统登录启动：机器、网络和本地服务必须可用，登出或重启后的持续运行需要另行实际验证。无变化时不重复通知；出现实质进展、失败或需要用户操作时报告。

准确的当前日期、声明、证据路径与未完成门记录在本地 `HANDOFF.md`。对外发布时以 `docs/HANDOFF_PUBLIC.md` 为准。
