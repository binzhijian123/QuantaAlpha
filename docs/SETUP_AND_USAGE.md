# 安装、配置与使用说明

## 适用范围

这是 Python + React 的本机研究工作台。每位部署者提供自己的 API 凭证、模型权限、Python 环境和 Qlib 数据。API Key 属于后端这次安装，默认参数与挖掘方向属于当前浏览器；共享一台后端的用户也共享后端配置，本项目没有独立账户的凭证隔离。

自动影子盘的独立 V10 入口及启用门禁见 [V10 自动运行接线](V10_RUNTIME_PLAN.md)。普通安装仍使用下方 `local_app.py`；复制代码不等于取得行情资格、完成校准或启用自动交易。使用者必须提供自己的数据与配置，不应复制开发工作机的声明和账本。

## 准备环境

需要 Python 3.10+、Conda 和 Node.js 18+（含 npm）。在仓库根目录执行：

```bash
conda create -n quantaalpha python=3.10
conda activate quantaalpha
pip install -e .
pip install -r frontend-v2/backend/requirements.txt
cd frontend-v2
npm ci
npm run build
cd ..
python frontend-v2/backend/local_app.py
```

打开 http://127.0.0.1:8000/ ，进入“设置”。首次安装可以直接在页面保存配置，后端会创建权限为 0600 的 `.env`。也可以先复制 `configs/.env.example` 为 `.env`，再填写自己的值。不要复制开发者的 `.env`、数据库或私有备份。

开发时可用 `bash frontend-v2/start.sh` 启动后端和 Vite（http://localhost:3000）。脚本使用 `scripts/qa_env.sh` 激活环境，默认查找当前用户的 `~/miniforge3`；其他安装位置或环境名可这样指定：

```bash
QA_CONDA_HOME="$HOME/miniconda3" CONDA_ENV_NAME=my-research bash frontend-v2/start.sh
```

环境名和 Python 安装必须在启动前准备好。网页显示当前解释器的检查结果，不会安装 Python/Conda、创建环境或替你切换正在运行的解释器。

## 在设置页配置

1. **配置 API**：填写自己的密钥、服务商提供的 HTTP(S) Base URL，以及完整的聊天模型和推理模型 ID。两者可以相同或不同，须与该服务账户可用模型一致，分别保存为 `CHAT_MODEL` 和 `REASONING_MODEL`。
2. **密钥留空**：保存时保留服务器已存密钥。页面只显示“已配置/未配置”，不回传原密钥或片段。新输入密钥不写入浏览器 localStorage，保存成功后会清空输入。
3. **数据路径**：填写后端所在电脑可访问的 Qlib Provider 目录，应包含 `calendars/day.txt`、`features/`、`instruments/`；填写结果输出目录。相对路径以仓库根目录为基准。浏览器所在设备的路径不能替代后端路径。
4. **保存配置**：只有后端写入成功才显示成功；失败会保留未保存状态，修改后重试。API 与数据配置用于后续新任务，已启动的挖掘/回测不会被追溯修改。配置值不支持换行、控制字符或 Shell 展开字符 `$`、反引号。
5. **环境与说明**：保存后刷新检查。结果只检查 Python、核心依赖、已填写的 API 配置、数据目录结构和目录权限。它不会调用外部 LLM，因此“后端已连接”或“API 配置完整”都不等于 API 鉴权、账户额度、模型调用或研究数据业务资格通过。

首次使用需要自行获取有权使用的 Qlib 数据；源码不包含行情、因子库、回测缓存或既有用户结果。可使用仓库现有的 `scripts/install_investment_data_release.py` 独立安装日线，再在设置页填写安装路径；下载前应确认网络与磁盘空间。

```bash
python scripts/install_investment_data_release.py --help
```

## 挖掘与回测

1. 在“默认参数”和“挖掘方向”配置本浏览器的新任务默认值。
2. 回到“因子挖掘”，输入研究方向并启动任务。该步骤会调用自己配置的 LLM，可能按自己的服务商账户计费；环境检查本身不会调用。
3. 在任务进度与诊断中查看执行情况。遇到鉴权、模型不存在或缺少数据的错误，先核对配置、权限与数据，再重试。
4. 在“因子库”查看生成结果，在“回测”选择因子库和模式运行样本外评估。没有自己的因子或缓存时，列表为空是正常初始状态。
5. 参数、回测期间和数据覆盖应按研究目标自行核对。不要把测试通过或页面有净值理解为盈利证明。

## 常见问题

- **保存失败**：确认后端在线，安装目录可写，地址格式为 HTTP(S)，字段中没有换行或 Shell 展开字符；页面保持未保存状态时不要当作成功。
- **依赖缺失**：在当前后端所用的 Conda 环境中执行安装命令，重启后刷新检查。不要只在另一个终端环境安装。
- **路径检查失败**：确认路径属于后端电脑，且指向 Provider 根目录；不要指向压缩包或只包含部分字段的子目录。
- **端口已占用**：先确认端口所属服务，复用或通过该服务的管理入口停止它；不要无差别强杀占用进程。
- **不同设备设置不同步**：浏览器参数和方向是本浏览器偏好；API 和数据路径是这台后端的公共配置。

## 自动影子盘与交接

当前自动影子盘仍处于恢复阶段，默认不应开启日频维护、盘中采集和策略 worker。需要独立协议、来源资格与未来运行验收，不能复制历史声明直接启动或回填漏日。旧 `app.py` 保留用于历史完整性；用户配置功能通过新 `local_app.py` 入口提供，新入口未被旧 V9 声明覆盖。

阅读 [发布交接文档](HANDOFF_PUBLIC.md) 了解当前状态和接续步骤。用户已授权先同步源码至 GitHub 并列明卡点。自动影子盘仍未验收，基础网页/API 健康不能替代真实运行门禁。

## 官方成分表派生（可选）

只有运行 `scripts/build_current_membership_provider.py` 解析官方 XLS 时额外需要 `xlrd`：在同一 Python 环境执行 `pip install -r requirements/release.txt`。普通网页/API 配置和使用不需要此步骤。源码不提供工作机数据或真实冻结声明，不能直接复用示例启用自动影子盘。

## 运行测试

在仓库根目录执行 `python -m unittest discover -s tests -p 'test_*.py'`。未提供历史研究因子库及其原始缓存、审计文件或原部署校准Provider时，相应外部原件集成检查会明确跳过；不会以伪造数据代替真实证据。其余测试使用临时或合成数据。测试通过不能替代全新环境安装或真实自动运行验收。
